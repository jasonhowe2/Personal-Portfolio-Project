MLB Hitting vs. Pitching: Predicting Team Wins

An end-to-end machine-learning project testing how well MLB team wins can be predicted from hitting statistics compared with pitching and run-prevention statistics.

View GitHub Repository View Notebook

1. Machine-Learning Problem

Research Question

How well can MLB team wins be predicted using hitting statistics compared with pitching/run-prevention statistics?

The target variable is W (team wins), so this is a regression problem. The unit of analysis is one MLB team in one season. The project compares hitting-only, pitching-only, and combined feature sets using two regression algorithms.

This project predicts final-season wins from season-level statistics. It is a predictive analysis rather than a causal study, so the results should not be interpreted as proving that a particular type of performance causes wins.

2. Context & Supporting Research

Winning baseball teams need to create runs while also preventing opponents from scoring. Modern baseball analysis uses a combination of traditional statistics and rate-based measures to describe offensive and pitching performance. This project applies those ideas to a supervised-learning problem at the team-season level.

The project uses credible baseball/statistical references for background and variable definitions:

  1. Baseball-Reference. (n.d.). Major League Baseball statistics and history. Baseball-Reference.
  2. FanGraphs. (n.d.). FanGraphs Library Glossary. FanGraphs.

4. Data Preparation

Python and pandas were used to load the team-season data and engineer the modeling variables. The selected predictors are numeric, so categorical encoding was not necessary. KNN requires variables to be on comparable scales, so the KNN models use StandardScaler inside a pipeline.

Engineered features

  • Runs per game: R / G
  • Home runs per game: HR / G
  • On-base percentage: (H + BB + HBP) / (AB + BB + HBP + SF)
  • Slugging percentage: total bases / AB
  • Runs allowed per game: RA / G
  • ERA: earned run average from the Lahman dataset
  • Strikeouts per 9 innings: SOA converted from innings/outs and scaled to nine innings

Missing values in the selected modeling columns are removed before the train/test split. The analysis also checks summary statistics and correlations before modeling to identify distributions and relationships that inform feature selection.

5. Data Understanding & Feature Selection

Exploratory analysis examines team wins against runs scored, runs allowed, and ERA, along with a correlation table for the selected predictors. The analysis treats the target as continuous, so class-imbalance analysis is not applicable.

HittingRuns/game, HR/game, OBP, and SLG capture run creation and offensive quality.
PitchingRuns allowed/game, ERA, and SO/9 capture run prevention and strikeout ability.
Rate-basedRates make teams more comparable across seasons with different game environments.
CombinedThe final feature set tests whether offense and run prevention add complementary information.

6. Training & Testing Strategy

The data are separated chronologically:

SplitSeasons / observations
Training2000–2022 — 690 team-season records
Testing2023–2025 — 90 team-season records

A chronological holdout keeps the most recent seasons unseen during model training. This is preferable to randomly mixing seasons because baseball performance environments can change over time. The test set is used only for final held-out evaluation, while scaling for KNN is fitted within the training data through a pipeline.

7. Baseline Performance

The baseline predicts the mean training-set win total for every team in the test set. This establishes a simple reference point: a machine-learning model should improve on a constant mean prediction to demonstrate useful predictive value.

The notebook calculates the baseline MAE, RMSE, and R² before comparing the two machine-learning models. This baseline is evaluated on exactly the same 2023–2025 test observations as the model results.

8. Model Development & Comparison

Two regression approaches were tested:

  • Linear Regression: provides a straightforward, interpretable linear benchmark.
  • K-Nearest Neighbors Regression (k = 7): can capture nonlinear relationships among similar team-seasons. Standardization is applied because KNN is distance-based.

Each model was trained three ways: with hitting features only, pitching/run-prevention features only, and the combined feature set.

9. Model Evaluation

The models are evaluated with three regression metrics. MAE is the average absolute prediction error in wins. RMSE is also measured in wins but gives more weight to larger errors. R² measures the proportion of variation explained relative to a mean-prediction baseline.

Among the tested models and feature sets, the combined KNN model had the lowest held-out MAE and RMSE and the highest R². Pitching/run prevention also performed somewhat better than the selected hitting variables when each group was modeled separately.

10. Model Interpretation & Error Analysis

KNN does not provide ordinary linear coefficients, so interpretation focuses on held-out predictions, actual-versus-predicted comparisons, and the largest prediction errors. The notebook also fits a combined linear regression model so the direction of the linear coefficients can be inspected.

The error-analysis table identifies the team-seasons with the largest absolute prediction errors. These cases help show where the selected statistics may be missing important information such as defense, baserunning, injuries, roster construction, park effects, bullpen usage, or schedule strength.

11. Ethics, Limitations & Real-World Use

  • The data are observational and aggregated at the team-season level, so the model does not establish causation.
  • The selected variables do not capture every contributor to wins, including defense, baserunning, injuries, roster construction, payroll, park effects, and strength of schedule.
  • The test period contains only three seasons, so performance could differ on another time period.
  • The 2020 season had a shortened schedule, which is an additional limitation when comparing raw win totals across the full period.
  • Incorrect predictions are relatively low-stakes in this educational project, but a real model used for betting, personnel, financial, or operational decisions could have greater consequences.
  • Predictions should be treated as estimates rather than guarantees.

Conclusion

For the selected MLB team-season data, pitching/run prevention produced somewhat stronger standalone predictions of wins than the selected hitting variables, while combining hitting and pitching information produced the strongest results among the tested approaches. The final KNN model achieved an MAE of 6.32 wins, RMSE of 8.12 wins, and R² of 0.559 on the held-out 2023–2025 seasons. These results describe predictive performance rather than a causal effect of hitting or pitching on wins.
